PROJECT OVERVIEW

프로젝트 개요

음성 인식과 LLM을 결합해 사용자의 말을 구조화된 데스크톱 인터페이스로 변환하는 AI 인터랙션 프로젝트입니다. AI가 모든 행동을 대신하는 에이전트가 아니라 사용자의 의도와 기존 프로그램 사이를 연결하는 인터페이스 어댑터로 작동하도록 설계했습니다.

TYPE
개인 AI 인터랙션 프로젝트
ROLE
기획 · Interaction Design · MVP 검증
INPUT
한국어 음성 인식
CORE
Schema-driven UI · LLM
STATUS
MVP 개발 및 음성 파이프라인 검증
01

말을 UI로 변환

자연어를 그대로 실행하지 않고 구조화된 스키마와 확인 가능한 UI로 변환합니다.

02

Human-in-the-loop

AI가 최종 행동을 독점하지 않고 사용자가 검토하고 수정한 뒤 실행합니다.

03

기존 도구를 연결

새로운 만능 앱보다 기존 데스크톱 프로그램의 기능을 하나의 호출 인터페이스로 묶습니다.

DESIGN / SYSTEM

설계와 구현

음성 호출형 인터페이스

사용자는 복잡한 메뉴를 탐색하는 대신 원하는 결과를 말합니다. 페르낭은 발화를 분석해 필요한 도구와 입력값을 추출하고 실행 전에 구조화된 화면으로 보여줍니다.

Schema-driven UI

LLM이 자유 형식 화면을 직접 생성하지 않고 사전에 정의된 컴포넌트와 스키마 안에서 UI를 조합하도록 설계했습니다.

한국어 음성 인식 MVP 검증

초기 실험에서는 상시 마이크 스트림과 Whisper 한국어 롤링 인식을 사용했으며 2.8초 창에서 짧은 발화와 주변 소리를 문장으로 오인식하는 문제가 나타났습니다.

한국어 음성 데이터 학습 계획

음성–텍스트 쌍 12,854개, 총 약 12시간 51분의 데이터셋을 학습용 원재료로 분석했습니다. 원본 음성은 제품에 포함하지 않고 학습 결과 모델만 배포합니다.

ROLE / RESPONSIBILITY

담당 작업

LLM을 행동 주체로 과대평가하지 않고 사용자 통제와 기존 도구의 연결성을 중심으로 제품 역할을 제한했습니다.

  1. 01
    제품 역할 정의

    AI 에이전트가 아니라 인터페이스 어댑터로 범위를 설정했습니다.

  2. 02
    Human-in-the-loop 설계

    생성된 행동을 사용자가 확인·수정한 뒤 실행하도록 구성했습니다.

  3. 03
    음성 인식 실험

    Whisper 기반 한국어 롤링 인식의 오인식 사례를 수집하고 분석했습니다.

  4. 04
    스키마 기반 UI 구조

    LLM 출력이 정해진 컴포넌트 구조 안에서 표시되도록 설계했습니다.

  5. 05
    데이터 배포 원칙

    원본 음성은 학습용으로만 사용하고 배포물에는 모델만 포함하도록 정했습니다.

REFLECTION

음성 인터페이스는 인식 정확도만 높인다고 완성되지 않습니다. 잘못 들었을 때 무엇을 실행하지 않아야 하는지, 사용자가 얼마나 쉽게 수정할 수 있는지가 신뢰를 결정합니다.
