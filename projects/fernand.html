03 / DESKTOP WORKSPACE

FERNAND

일정이 아니라 작업의 맥락까지 남기는 데스크톱 작업 공간

PROJECT OVERVIEW

작업 목록이 아니라, 내가 왜 이렇게 일하고 있는지를 보여주는 도구.

Fernand는 Windows 데스크톱에 상주하는 개인 작업 보조 환경입니다. 위젯을 배치하는 Board와 오늘·예정 작업을 다루는 Work, 병렬 작업의 흐름을 표현하는 Track을 하나의 공간으로 묶습니다.

핵심 문제는 일정 자체보다 작업의 맥락이 사라지는 것이었습니다. 무엇을 해야 하는지만 기록하면 우선순위가 왜 바뀌었는지, 어떤 판단으로 작업을 미뤘는지, 여러 프로젝트가 어떻게 동시에 움직이는지가 남지 않습니다. 그래서 Track을 단순 일정 그래프가 아니라 자기 피드백과 판단 기록을 위한 구조로 재정의했습니다.

TYPE

01

상시 작업 공간

창 모드와 전체화면, 트레이 상주를 오가며 필요한 순간에 빠르게 꺼내 쓰는 데스크톱 도구로 설계합니다.

02

맥락이 남는 Track

병렬 작업과 순서를 보여주는 것에 그치지 않고 변경 이유와 판단 시점을 함께 남기도록 구조를 확장합니다.

03

도구 자체가 먼저

AI를 제품의 정체성으로 두기보다 Board, Work, Track의 사용성이 독립적으로 성립하도록 우선순위를 둡니다.

PRODUCT / UX

설계와 구현

Board는 기능 목록이 아니라 지속적인 공간입니다.

시계, 타이머, 메모, 체크리스트, 캘린더 같은 위젯은 일회성 팝업이 아니라 사용자가 위치와 상태를 기억하는 Fernand Space 안에 존재합니다. 편집 모드에서는 배치와 복제, 삭제를 분리해 평상시 오조작을 줄였습니다.

성능 문제를 줄이기 위해 위젯의 활성·정지·폐기 상태를 구분하고, 화면 밖 요소를 불필요하게 갱신하지 않는 방향으로 구조를 정리했습니다.

Track의 핵심을 일정에서 자기 피드백으로 바꿨습니다.

초기 Track은 여러 작업 레인을 병렬로 보여주는 데 집중했습니다. 하지만 실제 사용에서는 ‘무엇이 다음인가’보다 ‘왜 이 순서가 됐는가’가 더 빨리 사라졌습니다.

따라서 작업 블록의 연결보다 변경 이유, 판단 시점과 다음 액션이 흐름 안에 남도록 설계를 수정하고 있습니다. 전체 Track은 오늘을 기준으로 열리고, 여러 레인의 작업 중 당장 해야 할 일을 다시 정리해 보여주는 역할을 갖습니다.

데스크톱에서 사라지지 않되, 방해하지 않아야 합니다.

Fernand는 작업 중 계속 살아 있는 도구이기 때문에 일반 앱보다 창 상태와 포커스, 듀얼 모니터, 메모리 사용량이 UX에 직접 영향을 줍니다. 창 모드와 전체화면 전환, 사이드바, Pet, 패널의 포커스 복귀 규칙을 별개의 세부 기능이 아니라 하나의 데스크톱 행동 규칙으로 다룹니다.

ROLE / RESPONSIBILITY

담당 작업

제품 방향과 Work/Track UX를 중심으로 기능 우선순위와 데스크톱 상호작용 규칙을 설계하고 일부 구현을 담당했습니다.

  1. 01
    제품 구조와 우선순위

    Board / Work / Track의 역할을 분리하고 각 화면이 해결해야 하는 사용자 문제를 정의했습니다.

  2. 02
    Track 정보 구조

    병렬 레인, 순서, 오늘 기준 탐색과 변경 이유 기록을 하나의 작업 흐름으로 설계했습니다.

  3. 03
    Desktop UX

    창·전체화면·트레이·포커스·사이드바 등 상시 실행 앱의 상태 전환 규칙을 정리했습니다.

  4. 04
    성능 기준

    위젯 라이프사이클, 뷰포트 컬링과 진단 지표를 통해 사용 중 불필요한 렌더링을 줄이는 방향을 잡았습니다.

REFLECTION

일정을 더 정교하게 보여주는 것만으로는 프로젝트 관리가 되지 않았습니다. 작업이 바뀌는 이유와 그 판단이 남아야 사용자가 나중에 자신의 작업 방식을 되돌아볼 수 있었습니다.

Fernand를 반복해서 수정하며 기능 수보다 중요한 것은 화면마다 사용자의 질문이 하나씩 명확해야 한다는 점을 확인했습니다. 이후 설계에서는 새로운 기능을 추가하기 전에 그것이 Board, Work, Track 중 어느 문제를 해결하는지부터 검증하고 있습니다.
